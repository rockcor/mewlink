# MewLink 产品与安全设计（MVP）

## 1. 产品目标

MewLink 用一对造型不同的原创常驻卡通桌宠承载情侣间低负担、可忽略的“环境式陪伴”。两只宠物同时出现：一只代表自己并反映本机活动，另一只代表伴侣并承载对方状态、互动和异步回放。伴侣只发送提醒喝水和拥抱两种动画；喝水事件可携带允许列表中的杯型。跨时区时，接收方上线后看到一段压缩回放，而不是一串通知。

成功标准：首次绑定不超过 2 分钟；原始屏幕与窗口标题永不离开本机；服务端无法读取情侣内容；互动不会打断专注；离线 24 小时后仍能完整同步；常驻资源占用可控。

## 2. 非目标

- 不做员工监控、精确工时、应用使用排行榜或伴侣位置追踪。
- 不上传截图、OCR 文本、窗口标题、文件名、URL 或键盘内容。
- 不承诺从内容推断情绪、生产力或行为意图。
- MVP 不做群组、公开社交、跨情侣历史迁移、云端搜索和永久云备份。
- 差分隐私不用于掩盖逐条实时状态；实时状态通过最小化、降频和 E2EE 保护。

## 3. 威胁模型

保护对象：关系身份、设备公钥、粗粒度状态、互动、时间线和本地密钥。对手包括被攻陷/好奇的中继服务、网络窃听者、撞库者、拿到旧设备的人、恶意伴侣及第三方应用。

保证：传输 TLS + 消息 E2EE；服务端只见信封大小、路由标识和大致时间；设备撤销后不能解密新消息；重放与篡改被检测；本机分类器不输出敏感原文。

不保证：已解锁且被恶意软件控制的终端、截图/肩窥、伴侣根据互动时机进行的社会推断、服务端流量分析。应通过固定大小填充、批量/抖动发送、阻止/解除绑定、30 天信封 TTL 和安全日志缓解。

## 4. 隐私模型与分类边界

数据分三级：

1. **原始信号（仅内存）**：前台进程标识、输入空闲秒数、锁屏状态，以及最近一次输入属于键盘还是指针。进程标识只在 Rust 原生层与本地规则匹配，不进入前端；输入只读取事件发生时间，不读取按键值、指针坐标或手势内容。绝不读取窗口标题、屏幕像素、文档、URL 或音频。
2. **本地派生状态**：七类之一、置信度区间、起止时间。进程标识经本地规则匹配后立即丢弃；用户可覆盖分类或将应用列为“始终私密”。
3. **同步状态**：最短持续 5 分钟、时间取整到 5 分钟的状态段；默认延迟批量发送。实时“现在忙碌”是用户显式开启的独立选项。

分类优先级：`locked => rest`；空闲超过 10 分钟 => `rest`；空闲 2–10 分钟 => `idle`；已知会议应用通话态 => `meeting`；本地媒体类别 => `video`；其余由仅含进程类别的本地规则产生。无法可靠判断时使用 `browsing` 或不发送，不猜测具体内容。

### 差分隐私

DP 只用于需要同步的聚合统计（例如“今天大约 coding 多久”），不用于逐条互动。每设备每日隐私预算 `ε=1.0, δ=0`，按七类各分配 `ε=1/7`。每类分钟数先截断至 `[0, 480]`，加入离散 Laplace 噪声（敏感度 15 分钟，结果再夹紧），只发布 15 分钟粒度。预算账本保存在本地，重试复用同一噪声样本，避免平均攻击。MVP 默认关闭聚合分享；上线前需用独立测试向量审计采样器。状态时间线不声称具备 DP，而依赖数据最小化、取整、限频、E2EE 与保留期。

## 5. E2EE、密钥与设备绑定

每个设备首次启动生成 Ed25519 身份签名密钥与 X25519 设备密钥，私钥进入 macOS Keychain / Windows Credential Manager（由 Rust 层调用系统安全存储），不可导出。绑定使用一方展示的短期 QR：关系 ID、设备公钥、一次性邀请公钥、过期时间和人工比对的 6 位安全码。双方线下/带外比对后确认，服务端只登记签名后的设备公钥。

关系建立后使用 X3DH 风格握手派生共享根密钥，随后每设备对运行 Double Ratchet；MVP 在引入经审计的 ratchet 库前，使用 libsodium `XChaCha20-Poly1305` + HKDF 派生的每事件唯一密钥、单调发送序号和随机 192-bit nonce。每封信含 `protocolVersion, relationshipId, senderDeviceId, recipientDeviceId, keyId, sequence, nonce, ciphertext`，元数据作为 AEAD AAD。服务端不获得明文事件类型或精确事件时间。

新增设备必须由已验证设备签名授权；为新设备分发新的关系 epoch key，不自动复制历史。撤销设备会轮换 epoch，后续事件不能由旧设备解密。多设备分别加密同一事件的内容密钥；任何序号回退、重复 nonce、未知设备或过期 epoch 均拒收。密钥丢失时重新绑定，MVP 不提供服务端密钥恢复。

## 6. 状态机

活动状态机：`unknown -> active(category) -> idle -> rest`。锁屏立即进入 `rest`；解锁且出现输入后重新采样；类别需连续 30 秒才提交，防抖；状态段最短 5 分钟才同步。用户手动设定 `private` 时暂停状态发送。

互动状态机：`composed -> queued -> encrypted -> uploaded -> delivered -> acknowledged -> expired`。专注模式下 `delivered -> cached`，退出后按频率规则回放。静音时保留收件箱但不动画；阻止后拒收并轮换关系密钥。

回放状态机：`collecting -> ready -> playing -> paused/skipped -> completed`。将连续同类状态合并，24 小时压缩为最多 30 秒；互动有更高权重但每分钟最多一次动画。事件以 UTC 时间排序，播放时同时还原发送方当时的本地时间并换算为接收方当地时间。

## 7. 事件协议

明文仅存在于端点：

```ts
type PlainEvent = {
  id: string; version: 1; relationshipId: string;
  senderDeviceId: string; createdAt: string;
  senderUtcOffsetMinutes?: number;
  kind: 'activity.segment' | 'interaction' | 'receipt';
  payload: ActivityPayload | InteractionPayload | ReceiptPayload;
};
```

`senderUtcOffsetMinutes` 是发送当时按 15 分钟取整的 UTC 偏移，只存在于 E2EE 密文内；不读取或同步城市、时区名称。接收端根据事件绝对时间和自己的历史夏令时偏移换算回放时钟；旧事件缺少该字段时只显示接收方本地时间。`activity.segment` 含类别、取整后的开始/结束时间；`interaction` 含允许列表中的动作、可选杯型和可选本地化短语 ID，不允许任意文本进入 MVP；`receipt` 仅确认事件 ID 与状态。客户端验证版本、字段长度、允许值、时间偏差和签名后再持久化。事件 ID 使用 UUIDv7（骨架暂用 UUIDv4）。同一 ID 幂等；每设备序号防重放；协议升级采用显式版本，未知版本隔离而非丢弃。

## 8. 数据模型

本地 IndexedDB 原型含 `events`（加密信封或本机 mock 明文、方向、投递态）、`activitySegments`、`replayCursor`、`privacyBudget`。生产版迁至 Rust/SQLite + SQLCipher，密钥来自系统安全存储。服务端只有 `users`、`relationships`、`devices`、`prekeys`、`mailbox_envelopes`、`push_tokens` 和 `revocations`；信封按接收设备分片，确认或 30 天后删除。

## 9. 后端最小方案

一个无状态 API（Rust/Axum 或 TypeScript）+ PostgreSQL + 对象大小受限的信封表：注册设备、发布/领取 prekey bundle、上传信封、长轮询/WebSocket 拉取、确认、撤销。APNs/WNS 推送只携带“有新信封”的不透明提示。限流按设备签名和关系配额，服务端时钟不写入 E2EE 负载。部署日志禁止记录请求体、token 和关系图；备份继承 30 天删除策略。

## 10. 桌面权限与平台差异

macOS：透明无边框 NSWindow、`alwaysOnTop`，可选点击穿透；空闲秒数与键盘/指针最近事件时间通过 Core Graphics 读取，锁屏状态通过 CGSession 会话字典读取，前台应用通过 NSWorkspace 取得后在 Rust 内映射为粗类别。不会把应用名、输入内容、坐标、窗口标题或屏幕像素送入 WebView。若未来读取窗口标题或会议麦克风态，必须单独解释并请求辅助功能/麦克风权限，MVP 不请求。登录启动需用户显式开启。

Windows：透明无边框 WebView2 窗口；空闲用 `GetLastInputInfo`，锁屏通过输入桌面的可切换状态保守判断（锁屏或安全桌面都视为 `rest`），前台进程用 `GetForegroundWindow` + PID 并在 Rust 内映射。鼠标/触控板移动通过光标是否变化区分；其余新输入只标记为键盘/触控节奏，不读取键值。避免 UIAccess、键盘钩子和屏幕捕获。安装器需 WebView2 检测、代码签名及 SmartScreen 声誉建设。

共同要求：权限按需请求，可在设置页逐项关闭；分类器在 Rust 端暴露最小枚举，不向 WebView 传进程名。Linux 仅为开发 fallback，不在 MVP 支持范围。

## 11. 防骚扰

接收方拥有最终控制权：全局静音、按动作静音、每日勿扰时段、每位伴侣频率上限、专注时缓存、单次跳过、解除绑定与阻止。默认每 10 分钟最多 1 个主动动画、每小时最多 6 个；拥抱不能绕过限制。发送方只看到投递回执，不看到“是否遵从喝水”等行为结果。

## 12. MVP 里程碑

1. **本地原型（当前骨架）**：启动后贴靠工作区右下角的一对完整透明抠图桌宠；自己与 TA 使用不同造型并同时出现，TA 宠物承载互动与回放；悬停展开拥抱、个性化水杯与回放，单击 TA 宠物拥抱、双击提醒喝水；包含 coding、reading、meeting、video、browsing、idle、rest 状态，键盘/鼠标/触控板节奏动画，独立拥抱/喝水动作，以及 idle/lock/前台应用探针、加密信封模型、本地事件库和双端 mock。状态图缩小至 768×512，加密模块按需加载；活跃时以 500ms、离开时以 900ms、锁屏时以 5 秒间隔采样，以兼顾输入响应和资源占用。
2. **平台探针**：macOS/Windows 原生空闲与锁屏、规则分类、托盘设置、权限说明；性能/功耗测试。
3. **真实 E2EE**：系统密钥库、设备邀请、prekeys、经审计 ratchet、测试向量、撤销与轮换。
4. **中继与可靠性**：邮箱 API、离线同步、收据、推送、配额、删除与灾难恢复。
5. **安全 Beta**：第三方审计、滥用/阻止流程、隐私 UX、签名安装包、50 对跨时区测试。

上线门槛：不得把当前 mock 密钥、浏览器 IndexedDB 或前端 libsodium 演示当作生产 E2EE；必须完成原生密钥保管、正式握手/ratchet、协议审计和两平台权限测试。
